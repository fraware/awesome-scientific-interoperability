# Editorial Policy

## Mandatory Admission Tests

A resource enters the main list only when every test passes.

1. **Direct contribution:** It defines, implements, maps, validates, tests, registers, packages, preserves, or demonstrates an interoperability mechanism.
2. **Sentence test:** The connected objects or systems and the documented mechanism can be named precisely.
3. **Inspectability:** A specification, schema, API, ontology, implementation, validator, mapping, test suite, or substantial demonstrator is publicly inspectable.
4. **Maintenance:** The resource is actively maintained, stably governed, or institutionally stewarded.
5. **Exceptional quality:** The editor can recommend it as one of the strongest available examples for its function.
6. **Distinctive value:** It adds decision value beyond stronger entries already present.
7. **North-Star utility:** Its inclusion helps answer a concrete scientific integration question.

## General Standards

A general web, software, identity, or policy standard belongs only when scientific profiles or implementations make it indispensable to understanding a concrete scientific interface. General importance alone is insufficient.

## Implementations

An implementation belongs when it is a canonical reference implementation, supports conformance, or demonstrates interoperability across multiple standards, languages, or independently maintained systems. Popularity alone is insufficient.

## Emerging Resources

An emerging resource requires a public technical artifact, credible stewardship, and at least one working implementation or substantial pilot. Announced projects and unfinished standards remain on the watchlist.

## Domain Standards

A domain standard belongs when it has explicit exchange semantics, multi-institutional stewardship, and multiple implementations or established institutional adoption. Domain exemplars should expose patterns useful beyond one field.

## Summaries

Each entry `summary` states what the resource is, which systems or objects it connects, and the mechanism enabling that relationship. Summaries must exactly match the README sentence, start with an uppercase character, end with a period, and avoid marketing language, institutional prestige claims, and guarantees of universal compatibility.

## Removal

Resources move to the archive when they are deprecated, abandoned, inaccessible, materially undocumented, superseded, or no longer among the strongest current options.
