# Project Charter

## Mission

Awesome Scientific Interoperability identifies the outstanding public mechanisms that allow independently developed scientific systems and objects to work together.

## North Star

A technically competent user should be able to identify the strongest available interoperability mechanism for a concrete scientific integration problem without conducting a new landscape search.

## Unit of Curation

The project curates an **interoperability contribution**, not merely a project or organization. Every accepted entry must complete this sentence precisely:

> **Resource** enables **X** to exchange, interpret, execute, preserve, or compose with **Y** through **documented mechanism Z**.

## Primary Users

- Research software engineers selecting formats, APIs, workflow interfaces, and packaging standards.
- Scientific infrastructure architects assembling repositories, compute services, knowledge systems, and laboratories.
- Data stewards selecting identifier, metadata, ontology, provenance, and access mechanisms.
- Scientific-agent developers exposing tools, data, capabilities, and evidence through reusable interfaces.
- Standards communities locating adjacent specifications, mappings, implementations, and test suites.

## Scope

The main list includes outstanding standards, protocols, formats, schemas, APIs, ontologies, identifiers, registries, reference implementations, mappings, validators, conformance suites, and reference architectures.

## Non-goals

The project is not a comprehensive scientific-software directory, FAIR bibliography, certification service, product ranking, generated database, or list of every implementation of every standard.

## Quality Bar

An entry must expose a reusable public contract, supply inspectable technical material, demonstrate credible maintenance or stewardship, add distinctive decision value, and withstand comparison with stronger alternatives.

## Operating Principle

The README is manually authored and authoritative. The indexed, section-scoped catalog validates consistency and supports maintenance; it never decides inclusion or generates the README.
